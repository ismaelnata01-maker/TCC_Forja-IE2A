IE2A — BACKEND EM TYPESCRIPT

OBJETIVO
Este projeto implementa somente o backend do IE2A. A API atende às telas de
login, perfil, início/catálogo, minha biblioteca e adicionar jogo. O frontend
do grupo pode consumir estes endpoints e continuar usando sua própria
implementação de Tailwind e componentes visuais. O arquivo public/images/image.png
continua disponível como logo do projeto.

TECNOLOGIAS
- TypeScript e Node.js: linguagem e ambiente do servidor.
- Express: criação das rotas HTTP.
- SQLite com better-sqlite3: banco local persistido em data/ie2a.sqlite.
- bcryptjs: armazenamento seguro de senhas com hash.
- JSON Web Token (JWT): autenticação das rotas privadas.
- Zod: validação de dados recebidos pela API.
- Helmet e CORS: cabeçalhos de segurança e acesso controlado pelo frontend.

ORGANIZAÇÃO DOS ARQUIVOS
- package.json: dependências e comandos do projeto.
- tsconfig.json: regras de compilação e verificação de tipos.
- .env.example: exemplo das configurações necessárias.
- .gitignore: evita versionar segredos, dependências e arquivos do banco.

- src/config.ts: lê e valida as configurações.
- src/database.ts: abre o SQLite, cria tabelas e inclui jogos de demonstração.
- src/express.d.ts: adiciona o identificador do usuário autenticado ao tipo
  Request do Express.
- src/app.ts: configura segurança, CORS, JSON, rotas e respostas de erro.
- src/server.ts: inicializa e encerra o servidor.
- src/middleware/auth.ts: valida o token Bearer nas rotas privadas.
- src/routes/auth.ts: cadastro, login e consulta dos dados da sessão.
- src/routes/profile.ts: consulta e atualização do perfil.
- src/routes/games.ts: busca, filtros, detalhe e cadastro de jogos.
- src/routes/library.ts: consulta e alteração da biblioteca de cada usuário.
- EXPLICACAO.text: este guia.

COMO EXECUTAR NO WINDOWS
Requisitos: Node.js 20 ou mais recente.

1. Abra um terminal na pasta que contém package.json.
2. Instale as dependências: npm install
3. Crie seu arquivo de configuração no PowerShell:
   Copy-Item .env.example .env
4. Abra .env e troque JWT_SECRET por uma chave própria de pelo menos 32
   caracteres. O valor de exemplo é apenas um marcador e não será aceito.
5. Se o frontend usar outra origem/porta, atualize FRONTEND_ORIGINS em .env.
6. Inicie o backend em modo de desenvolvimento: npm run dev
7. Teste a API no navegador: http://localhost:3000/api/health

Para verificar os tipos: npm run typecheck
Para compilar: npm run build
Para executar a versão compilada: npm start

O SQLite e as tabelas são criados automaticamente ao iniciar. Quatro jogos de
exemplo são adicionados somente quando o catálogo está vazio. O arquivo do
banco fica em data/ie2a.sqlite e não deve ser enviado ao Git.

AUTENTICAÇÃO
O cadastro e o login retornam um token JWT e os dados básicos do usuário.
Guarde o token no frontend e envie-o nas rotas privadas no cabeçalho:
Authorization: Bearer SEU_TOKEN

Cada usuário tem a própria biblioteca. O banco nunca retorna password_hash.
Senhas são verificadas com bcryptjs e os tokens expiram após sete dias.

ROTAS DA API
Públicas:
- GET /api/health
- POST /api/auth/register
  JSON: {"email":"pessoa@exemplo.com","password":"senha-com-8-caracteres",
         "displayName":"Nome"}
- POST /api/auth/login
  JSON: {"email":"pessoa@exemplo.com","password":"senha-com-8-caracteres"}
- GET /api/games?q=aventura&genre=Aventura&company=Team&limit=24&offset=0
- GET /api/games/:id

Privadas (requerem Authorization: Bearer <token>):
- GET /api/auth/me — dados básicos do usuário autenticado.
- GET /api/profile — dados do perfil e quantidade de jogos salvos.
- PATCH /api/profile — atualiza displayName e/ou avatarUrl.
- POST /api/games — cadastra um jogo.
  JSON: {"title":"Jogo","company":"Estúdio","genre":"Aventura",
         "description":"Descrição","coverUrl":"","storeUrl":"https://..."}
- GET /api/library — lista os jogos salvos pelo usuário.
- POST /api/library/:gameId — adiciona um jogo à biblioteca.
- DELETE /api/library/:gameId — remove um jogo da biblioteca.

As rotas que retornam listas usam o formato {"data":[...],"pagination":...}
(ou {"data":[...],"total":...} para biblioteca). Erros usam o formato
{"error":"mensagem"}; falhas de validação podem incluir uma lista "details".
IDs são inteiros. Os filtros de catálogo podem ser combinados.

CONTRATO PARA O FRONTEND
- Login/cadastro: use /api/auth/login ou /api/auth/register e guarde o token.
- Perfil: carregue /api/profile; altere com PATCH /api/profile.
- Início e catálogo: GET /api/games; para buscar, use q, genre ou company.
- Biblioteca: GET /api/library; use POST e DELETE em /api/library/:gameId.
- Formulário de adicionar jogo: POST /api/games com os campos acima.
- Imagem da capa e link da loja são URLs opcionais. O IE2A organiza os dados e
  direciona à loja; não hospeda nem distribui os jogos.

OBSERVAÇÕES
- Esta é uma base acadêmica local. Configure um JWT_SECRET forte e um CORS
  adequado antes de publicar o serviço na internet.
- A criação de jogos requer login, mas ainda não existe uma função de
  administrador ou moderação.
- O frontend e os componentes Tailwind não são alterados por este backend;
  sua equipe pode organizar o estilo em arquivos próprios de componentes.
